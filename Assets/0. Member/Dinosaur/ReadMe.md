## 1. 현재 상태 — 먼저 확인

일반 공격·즉사·사망·관전의 코드 연결이 반영되어 있고, 칼·가위의 일반 공격 설정도 저장되어 있다. 게임에서 시민 또는 살인마 역할을 배정받은 뒤 칼이나 가위를 들고 좌클릭하면 일반 공격을 요청한다. 즉사 기술은 입력키 미지정과 살인마 개인 미션 미배정으로 아직 잠겨 있다.

- 칼: `isWeapon = true`, `attackDamage = 40`, `attackInterval = 0.5`.
- 가위: `isWeapon = true`, `attackDamage = 20`, `attackInterval = 0.5`.
- 드라이버: 현재 일반 아이템이며 무기 설정은 기본값 false, 0, 0을 유지한다.
- `KillManager.instantKillKey`는 현재 None이다.
- GamePlay에 살인마 개인 미션이 배정되지 않으므로 즉사 기술은 잠겨 있다. 키만 지정해도 해금되지 않는다.
- 일반 공격은 개인 미션 완료를 요구하지 않는다. 시민·살인마 역할 배정과 유효한 장착 무기 설정이 필요하다.
- 일반 공격 수치는 사용자 지정에 따라 칼 40·가위 20·공통 간격 0.5초로 확정했다. 즉사 Q키는 여전히 제안 상태이며, 즉사 쿨타임 기본값은 15초다.
- 기존 캐릭터는 사망 애니메이션의 마지막 자세로 남는다. 별도 시체 프리팹과 증거 생성 기능은 구현하지 않았다. 최종 시체·증거 처리 방식은 결정 대기 중이다.

칼·가위의 일반 공격 데이터를 적용했으며, 시민도 살인마와 같은 무기·피해량·공격 간격으로 일반 공격할 수 있다. 즉사 입력키와 별도 시체·증거 처리 방식은 결정 대기 항목으로 남아 있다.

## 2. 이번 작업에서 바뀐 동작

### 공격 판정

- 일반 공격과 즉사 기술의 요청 경로를 분리했다.
- 호스트가 역할 배정 여부, 생존·탈출·게임 종료 상태, 공격 간격을 검사한다. 역할이 배정되기 전과 대기실에서는 공격할 수 없다.
- 일반 공격은 실제로 해당 플레이어가 보유한 아이템인지 확인하고, ItemData에 설정된 피해량을 적용한다. 기존 대상 판정을 유지하므로 시민도 살인마뿐 아니라 다른 시민을 공격할 수 있다.
- 호스트가 처리한 카메라 위치와 시점으로 대상을 다시 찾는다. 사거리 밖, 시선 뒤쪽, 벽에 가려진 대상은 맞지 않는다.
- 공격 범위 기본값은 Unity 거리 단위로 2다. 카메라 기준 광선 검사와 플레이어 간 거리 검사를 모두 통과해야 한다.
- 일반 공격이 빗나가도 공격 모션과 공격 간격은 적용된다.
- 즉사는 살인마만 배정된 개인 미션이 하나 이상 있고 모두 완료되었을 때 사용할 수 있다. 시민은 개인 미션을 완료해도 즉사를 사용할 수 없다. 미배정은 완료로 취급하지 않는다.
- 현재 즉사 판정에는 무기 장착 필수 조건이 없다. 개인 미션 해금, 생존 상태, 시선·거리, 쿨타임을 검사한다.
- 즉사와 일반 공격에는 공통 공격 간격 제한이 적용되며, 즉사는 별도의 쿨타임도 사용한다.

### 애니메이션·사망·관전

- Animator를 공용 플레이어의 모델 자식 `Player`에 연결하여 애니메이션 클립의 뼈 경로를 맞췄다.
- 기존 이동 상태를 유지하며 `Attack`, `Dead` 상태와 `Attack`, `AttackSpeed`, `IsDead` 파라미터를 연결했다.
- 호스트가 승인한 공격을 각 클라이언트의 캐릭터 Animator에서 재생한다.
- 사망하면 이동 및 SimpleKCC 충돌을 차단하고, 진행 중인 로컬 상호작용과 아이템 표시를 정리한다.
- 아이템 드롭은 기존 PlayerItemController의 사망 이벤트 처리를 재사용한다.
- 피격되거나 공격 모션을 재생하면 진행 중인 로컬 홀드·드래그 상호작용을 취소한다.
- 무기를 든 시민·살인마의 좌클릭이 공격과 일반 클릭 상호작용을 동시에 실행하지 않도록 분리했다.
- 사망 후 기본 5초가 지나면 사망 위치에서 별도의 관전자 Sphere로 전환한다. 본인 시점으로 바닥을 이동하며, 생존자의 시점을 따라가지 않는다.
- 관전자끼리만 반투명 구체와 시선 방향 표시가 보인다. 상세 설정과 검증은 10절을 참고한다.

## 3. 실행 순서와 조작

### 방 참가와 게임 진행

1. 동일한 프로젝트 버전으로 두 실행 환경을 준비한다. 예: Unity Editor 1개와 실행 빌드 1개.
2. `Assets/Scenes/Lobby.unity`에서 한 명이 방을 만들고 다른 한 명이 같은 방에 참가한다.
3. StandBy에서 이동·시점 회전·ESC 플레이어 목록과 방장 표시를 확인한다.
4. 준비 조건을 충족한 뒤 방장이 게임 시작을 요청하여 GamePlay로 이동한다.
5. 결과 화면에서는 방장이 대기실 복귀 버튼을 누른다. 연결된 참가자들이 함께 StandBy로 이동한다.
6. 방장이 나가 세션이 종료되면 연결 종료 안내의 로비 이동 버튼을 사용한다. 게임 도중 일반 참가자가 나가면 해당 참가자는 패배 처리되고 남은 인원으로 승리 조건을 다시 판단한다.

현재 Build Settings의 활성 씬은 Main, Lobby, StandBy, GamePlay다. 실제 사용 씬 이름은 `StandBy`이며 `StandBy_Test`가 아니다. 씬 이름·경로를 바꾸면 NetworkBootstrap의 직렬화 값과 Build Settings도 함께 확인해야 한다.

### 기본 조작

- WASD 또는 방향키: 이동.
- 마우스 이동: 시점 회전.
- Space: 점프.
- Left Shift: 이동 중 달리기. 생존자는 스태미나 소진 후 체력을 초당 10씩 사용하고, 관전자는 제한 없이 달린다.
- Left Control: 현재 이동 코드에서는 저속 이동에 사용된다. 별도 앉기 자세나 충돌체 높이 변경을 의미하지 않는다.
- 빈손으로 아이템을 보며 좌클릭: 아이템 줍기.
- G: 들고 있는 아이템 내려놓기.
- 아이템을 들고 우클릭: 해당 아이템이 제공하는 사용 기능 실행. 모든 아이템에 사용 기능이 있는 것은 아니다.
- F 누르기/떼기: 홀드 방식 미션 상호작용 시작/종료.
- ESC: 방 상세 UI 열기/닫기.
- V: 자신의 음성 송신 음소거 전환. 상대방 소리 수신은 유지한다.
- 칼 또는 가위를 든 시민·살인마의 좌클릭: 일반 공격. 칼은 피해 40, 가위는 피해 20이며 둘 다 공격 간격은 0.5초다.
- 즉사 기술: Inspector에 지정한 키. 현재는 None이며 Q는 제안 상태다.
- 관전 중 WASD·마우스·Left Shift: 본인 시점으로 이동·시선 회전·무제한 달리기. 관전자는 점프·공격·아이템·미션 상호작용을 할 수 없다.

### 기존 연결 기능

- 공용 플레이어의 체력 기본값은 100이며, 호스트가 피해·사망 상태를 결정한다.
- 스태미너 기본값은 최대 100, 달리기 소모 초당 20, 회복 초당 15, 회복 대기 1.5초다. Inspector 저장값이 있으면 그 값이 우선한다.
- 들고 있는 아이템은 본인에게 1인칭 모델, 다른 참가자에게 손 위치를 따라가는 월드 모델로 표시된다.
- 현재 공격 모션 연결은 캐릭터 Animator 기준이다. 1인칭 전용 손·쥐기·무기 휘두르기 애니메이션은 이번 작업에서 추가하지 않았다.
- 공용 Player 프리팹 카메라에 AudioListener를 연결하고 StandBy·GamePlay의 고정 카메라 AudioListener를 비활성화했다. 소리를 듣는 위치가 로컬 플레이어의 이동·관전 시점을 따른다. 원격 플레이어의 Listener는 기존 PlayerCameraController가 비활성화한다.
- 음성은 생존자 송수신 그룹과 사망자 송수신 그룹을 구분한다. 사망자는 관전자 그룹으로 송신하며 생존자·관전자 그룹을 듣는다. 탈출자는 송신이 차단된다.

## 4. 현재 무기 설정과 Inspector 변경 방법

칼·가위의 확정값을 실제 ItemData 에셋에 저장했다. 아래에서 현재 값과 Inspector 설정 위치를 확인할 수 있다.

### 일반 공격용 아이템

대상 데이터:

- `Assets/ScriptableObjects/Data/Item/KnifeData.asset`: 무기 사용 On / 피해 40 / 간격 0.5초.
- `Assets/ScriptableObjects/Data/Item/ScissorsData.asset`: 무기 사용 On / 피해 20 / 간격 0.5초.
- `Assets/ScriptableObjects/Data/Item/ScrewdriverData.asset`: 무기 사용 Off / 피해 0 / 간격 0초(기존 기본값).

이후 무기 값을 조정할 때 해당 데이터에서 다음 항목을 설정한다.

1. `Is Weapon` (`isWeapon`): 체크.
2. `Attack Damage` (`attackDamage`): 확정된 양수 피해량.
3. `Attack Interval` (`attackInterval`): 확정된 양수 공격 간격(초).
4. 기존 아이템 ID와 `First Person Prefab` 참조를 유지한다.

세 값 중 하나라도 유효하지 않으면 무기로 판정되지 않는다. 이전 자동 검사에서는 임시 피해 25를 사용했지만, 실제 저장된 피해량은 칼 40·가위 20이다. 공통 공격 간격은 0.5초다.

### 플레이어와 즉사 기술

실제 게임용 공용 프리팹은 `Assets/Prefabs/Player/Player.prefab`이다. 개인 폴더의 `Assets/0. Member/Dinosaur/Prefab/Player.prefab`과 혼동하지 않는다.

- 루트의 KillManager: `Kill Range` 기본 2, `Kill Cooldown Seconds` 기본 15, `Instant Kill Key` 현재 None.
- 루트의 SpectatorManager: `Spectator Delay Seconds` 기본 5.
- 루트의 PlayerAnimation: Animator는 자식 `Player`의 Animator, Attack Clip은 기존 공격 클립을 참조한다. 이번 작업에서 연결되어 있다.
- Animator Controller: `Assets/0. Member/Hyunwoo/HW_Anim/Player.controller`.
- 사용 클립: `Assets/0. Member/Taewoo/Anim_Use/ANM_Player_Attack.anim`, `Assets/0. Member/Taewoo/Anim_Use/ANM_Player_Die.anim`.

살인마 미션을 추가할 때는 `Mission/Mission Data`로 데이터를 만들고, Role Target을 Killer, Mission Type을 Personal로 지정한다. 고유 ID와 완료 횟수를 정한 뒤 GamePlay의 MissionSystem 미션 풀과 살인마 개인 미션 수를 확인한다. 실제 미니게임의 완료 요청도 MissionSystem으로 연결되어야 한다. 데이터만 만들거나 키만 지정해도 미션이 완료되는 것은 아니다.

배정된 살인마 개인 미션이 없는 상태에서는 즉사 잠금을 유지한다. 일반 공격은 해당 미션의 추가 여부와 무관하게 무기 설정을 통해 사용할 수 있다.

## 5. 변경 파일과 역할

전투 코드와 프리팹 연결은 아래 13개 파일에 반영되었다. 이후 확정된 무기 수치는 KnifeData.asset과 ScissorsData.asset에 추가했으며, ReadMe.md와 ReadMe.txt도 함께 갱신했다.

- `Assets/Scripts/KillManager.cs`: 시민·살인마 공통 일반 공격, 살인마 전용 즉사 요청, 호스트 판정, 공격 모션 동기화. 역할 정보가 늦게 도착한 Client에서도 연결을 다시 찾는다.
- `Assets/Scripts/Item/ItemData.cs`: 아이템별 무기 여부·피해량·공격 간격 설정.
- `Assets/Scripts/Player/PlayerItemController.cs`: 현재 실제 보유 중인 유효한 무기 조회.
- `Assets/0. Member/Dinosaur/Scripts/Player/Playercameracontroller.cs`: 호스트 조준 광선과 관전 시점 처리.
- `Assets/0. Member/Dinosaur/Scripts/Player/Playerhealth.cs`: 피해 상태를 통한 로컬 상호작용 취소 알림.
- `Assets/Scripts/Player/Detector/PlayerInteraction.cs`: 공격 입력 분리, 피격·공격·사망 시 상호작용 취소.
- `Assets/Scripts/Player/Detector/PlayerTargetDetector.cs`: 사망·탈출·게임 종료 후 상호작용 대상과 안내 제거.
- `Assets/Scripts/Player/Animation/PlayerAnimation.cs`: 공격 속도와 사망 Animator 상태 반영.
- `Assets/Scripts/Player/Movement/PlayerMovement.cs`: 사망 시 이동·충돌 차단.
- `Assets/Scripts/DeathManager.cs`: 사망 후 로컬 입력 상태 정리와 관전 전환 연결.
- `Assets/Scripts/SpectatorManager.cs`: 사망 5초 후 관전자 생성과 퇴장·씬 전환 시 정리.
- `Assets/Prefabs/Player/Player.prefab`: Animator 위치와 공격 클립 참조 연결.
- `Assets/0. Member/Hyunwoo/HW_Anim/Player.controller`: 공격·사망 상태와 전환 조건.

기존 방 참가·씬 전환은 Dinosaur/Scripts/Networking의 NetworkBootstrap과 PlayerSpawner, 음성·스태미너는 Dinosaur/Scripts/Player의 기존 컴포넌트를 사용한다. 이번 무기 데이터 설정에서는 이 기능들을 수정하지 않았다.

음성 재생 위치 수정은 `Assets/Prefabs/Player/Player.prefab`의 AudioListener 추가·참조 연결과 `Assets/Scenes/StandBy.unity`, `Assets/Scenes/GamePlay.unity`의 고정 Listener 비활성화에 반영했다. PlayerCameraController의 기존 InputAuthority 판정을 그대로 사용하며 음성 그룹·거리·벽 차단 규칙은 유지한다.

독립 실행 파일 2개로 실제 NetworkBootstrap의 방 참가 경로를 검사하면서, 게임 방에 2명이 입장해도 양쪽 Voice 클라이언트가 PeerCreated에 머물고 녹음·송신이 꺼진 문제를 재현했다. `Dinosaur/Scripts/Networking/NetworkBootstrap.cs`의 PrepareRunner에서 FusionVoiceClient를 Runner 콜백에 명시적으로 등록하도록 수정했다. 앞선 임시 씬 검사는 Runner를 직접 만들었으므로 이 실제 진입 경로의 누락을 검출하지 못했다.

### 실제 방 연결 수정 후 독립 실행 파일·마이크 검사

- Unity 2022.3.58f1 Windows 개발 빌드에 성공했다(빌드 오류 0개). 같은 PC에서 Host·Client 실행 파일을 각각 실행했다. 임시 검사 코드 제거 후 Unity 배치 컴파일도 종료 코드 0으로 통과했다.
- 실제 Lobby 씬의 NetworkBootstrap.PrepareRunner로 Runner를 구성하고 비공개 2인 방에 접속했다. 수정 전에는 양쪽 Voice가 PeerCreated에 머물렀고, FusionVoiceClient 콜백 등록 후에는 같은 음성 방에서 Joined·참가자 2명을 확인했다.
- StandBy에서 생성한 테스트음 청취, Host 마이크 → Client 수신·재생을 사용자가 직접 확인했다.
- 기존 준비 완료·게임 시작 RPC와 카운트다운을 거쳐 GamePlay에 진입했다. GamePlay에서 Client 마이크 → Host 수신·재생도 사용자가 직접 확인했다.
- 각 실행 파일에서 활성 AudioListener가 1개이며, 원격 Speaker 연결·디코딩과 실제 AudioSource·AudioListener 출력이 발생하는 것을 확인했다.
- 기존 시간 종료 처리 함수를 호출해 종료 상태를 만든 뒤 NetworkBootstrap.returnToStandBy로 복귀했다. 두 실행 파일 모두 StandBy에서 Voice Joined·참가자 2명·Listener 1개를 유지했고, 생성 신호의 양방향 재생을 확인했다. 실제 제한시간 전체를 기다리는 검사는 수행하지 않았다.
- 테스트 중 한쪽 송신을 음소거해 같은 PC의 마이크 피드백을 피했다. 프로젝트에 저장된 마이크 입력·음량·거리·채널 설정은 변경하지 않았다.
- 테스트는 방 참가와 준비·시작·복귀 함수를 호출하는 방식이다. 로비 UI 클릭·초대 서비스, 서로 다른 PC·마이크·네트워크 사이의 통화, 실제 사망 전후의 사람 목소리 채널 분리는 이번 검사에 포함하지 않았다.
- 임시 제어 파일 읽기 충돌이 한 번 발생했으나 파일 교체 방식으로 해결하고 검사를 계속했다. 게임 음성 코드의 오류와 구분한다. 검사 종료 후 실행 파일을 닫고 임시 검사 코드를 프로젝트에서 제거했다.

### 수동 플레이 확인 — 칼·가위 일반 공격 설정 적용 후

1. 두 실행 환경이 같은 버전인지 확인하고 같은 방에 참가한다. Host와 Client 양쪽에서 시민·살인마 역할의 공격을 각각 확인한다.
2. 살인마가 아이템을 주웠을 때 본인의 1인칭 표시와 상대방의 손 장착 표시를 확인한다. G로 내려놓은 뒤 다시 줍는다.
3. 시민과 살인마가 각각 칼 또는 가위로 다른 플레이어를 정면·사거리 안에서 좌클릭 공격한다. 체력 100·회복 없음 기준으로 칼만 사용하면 100 → 60 → 20 → 0으로 세 번, 가위만 사용하면 100 → 80 → 60 → 40 → 20 → 0으로 다섯 번의 정상 적중 후 사망해야 한다. 각 공격 사이에는 최소 0.5초를 둔다.
4. 벽 뒤·사거리 밖·뒤쪽 대상, 빈손, 공격 간격 이내의 중복 요청에는 피해가 적용되지 않는지 확인한다.
5. 시민은 개인 미션 완료 여부와 무관하게 즉사를 사용할 수 없어야 한다. 살인마 미션이 없으면 즉사 키를 지정해도 잠겨 있어야 한다. 실제 미션을 추가했다면 배정·완료 이후에만 즉사가 가능한지 확인한다.
6. 사망자의 아이템 드롭, 상호작용 안내 제거, 사망 자세, 이동·충돌 차단을 확인한다.
7. 살인마 1명·시민 1명인 2인 게임에서는 시민 사망으로 즉시 결과 화면이 열린다. 살인마 사망만으로 즉시 종료하는 기존 규칙은 없으며, 시민의 미션·탈출·시간 종료 조건을 계속 사용한다. 게임 진행 중 관전자 이동을 확인하려면 최소 3명으로 시민 1명이 사망한 상황을 검사한다. 사망 5초 후 본인 시점으로 바닥을 이동할 수 있어야 한다. 관전자끼리의 표시·음성을 검사하려면 생존자 1명과 관전자 2명을 유지한다. 결과 화면에서는 관전자 이동이 차단되고 복귀 버튼을 누를 커서가 유지되어야 한다.
8. 생존자와 사망자의 실제 음성 송수신, V 음소거, 게임 결과, 방장의 StandBy 복귀 버튼을 확인한다.
